# 快件段间延误分析

按「入分拣 → 出场 → 到件」把每条快件切成两段，演示晚补出场时间如何同时改变相邻两段、
改派如何改变网点归属，以及两种延误归因口径（按段分摊 / 最先超标段）为什么都不会把总延误多算。

只用 Node.js 内置模块，无第三方依赖。

## 启动

```bash
PORT=3000 node server.js
# 打开 http://127.0.0.1:3000
```

`PORT` 缺省为 3000，服务固定绑定 `127.0.0.1`。

## 页面上的三步

1. **生成原慢件分布**：按「随机种子 + 件数」生成可重复的虚构记录（固定基准日 2026-11-20），
   展示补交前的慢件 / 正常 / 时间不全分布与网点慢段责任。
2. **补交改派和出场**：应用当晚补交记录——为缺出场的件补出场（可能仍缺到件）、
   标记并改派一条运单；逐件列出状态、最先超标段和两段时长的前后变化。
3. **查看段间延误**：并列展示「分摊口径」与「最先超标口径」的归因结果、网点积压与传播、
   逐件的最先超标段解释，并做一致性自检。

页面业务结果区 `<main id="results" data-evidence-result>` 的取值随操作变化：
`未生成 → generate → late → segments`，便于核对操作前后内容。

「导出 CSV」保留时间不全的件（`missing_time` 列写明缺哪一段），
`change` 列并列展示补交/改派引起的变化。

## 口径

- **总延误**：每条快件各段「实测耗时 − 计划耗时」的正数部分之和。
- **分摊口径**：每段只承担自己超出的分钟。
- **最先超标口径**：整件延误全部记到最先超标的那一段，其后超标段视为后果、不重复计入。
- 两种口径的合计都等于总延误，`consistency` 自检与页面横幅会核对这一点。
- 缺任一时间点的件状态为「时间不全」，保留在分析与导出中；已测出的超标段仍会体现。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/generate?seed=&count=` | 生成演示数据（含待补交事件） |
| POST | `/api/analyze` | `{ shipments, lateAdditions, seed }`，返回前后快照与变化 |
| POST | `/api/segments` | 同上，返回两套口径、网点与解释清单 |
| POST | `/api/export` | 同上，返回 CSV 附件 |
